# DESIGN: Архитектура MVP и протоколы экспериментов

Цель: дать чёткое, воспроизводимое описание среды, агента, метрик и экспериментального протокола для MVP.

1) Формализация среды
---------------------

- Простая среда представляет одиночный перекрёсток с двумя конфликтующими движениями: NS (north-south) и EW (east-west).
- State s_t = (q_ns, q_ew), где q_* — целые числа, длины очередей прямо перед светофором.
- Action a_t ∈ {0,1}: 0 — даём зелёный NS; 1 — даём зелёный EW.
- Переходы: на каждом шаге происходят новые прибытия по пуассоновскому процессу с параметрами λ_ns, λ_ew. При зелёном направлении обслуживаются до C машин (пропускная способность фазы).
- Reward r_t = - (q_ns + q_ew) (минимизация общей очереди). Можно расширить: r = -sum(delay) или r = throughput - alpha * queue.

Параметры среды (по умолчанию в MVP):

- arrival_rates=(0.6, 0.4)
- capacity_per_green=2
- max_queue=50

2) Агент
---------

- Табличный Q-learning (offline, on-policy обновление каждой пары (s,a)->(r,s')).
- Гиперпараметры по умолчанию: α=0.1, γ=0.99, ε старт=0.3, ε_min=0.02 (линейное/экспоненциальное уменьшение).
- Представление состояния: текущие стохастические очереди (q_ns, q_ew). Для масштабирования возможны дискретизация/бекетинг очередей (0,1,2,3+).

3) Протокол обучения и оценки
----------------------------

Train:

- Запустить N_ep эпизодов, в каждом M шагов.
- Использовать эпсилон-жадную стратегию с decay для исследования.
- Сохранять Q-table после обучения.

Evaluate:

- Загружать Q-table и запускать K эпизодов с ε=0 (детерминированно), собирать метрики: среднее вознаграждение, средняя суммарная очередь, throughput.

4) Метрики
-----------

- Avg reward per episode
- Avg sum(queue) per step
- Throughput per episode
- Fraction of time each direction had green (fairness)
- Std of reward across runs (stability)

5) Логирование и репликация
--------------------------

- Логи: сохранять seed, arrival_rates, гиперпараметры агента, версия кода и Q-table.
- Для репликации фиксировать: seed окружения, seed RNG агента, версия зависимостей.

6) Формат данных для прогнозов
------------------------------

- Простейший формат CSV: `timestamp,location,flow_ns,flow_ew`.
- `forecast.py` предоставляет baseline: `moving_average_forecast(history, window)`.

7) Эксперименты и сравнения
----------------------------

Рекомендуемые эксперименты:

1. Baseline comparison: случайная политика vs табличный Q vs ручной фиксированный план.
2. Sensitivity to arrival rates: варьировать λ_ns/λ_ew, смотреть устойчивость.
3. Scalability: дискретизация состояний, расширение до N-перекрёстков (multi-agent).

8) Возможные улучшения
-----------------------

- MLP-функция приближения (DQN) для больших состояний.
- Multi-agent RL для сетей перекрёстков (MFQ, independent learners, centralized critic).
- Интеграция прогнозов в агент (predictive control): использовать прогнозы трафика как часть состояния.
- Интеграция реальных данных: добавить модуль загрузки CSV и предобработки.

9) Контроль версий и дальнейшие шаги
----------------------------------

- Рекомендуется заводить отдельную ветку `experiments/` для каждой серии экспериментов; хранить конфиги гиперпараметров.
- Далее могу: реализовать DQN-агента, добавить визуализацию траекторий, подготовить ноутбук с несколькими сравнительными графиками.
